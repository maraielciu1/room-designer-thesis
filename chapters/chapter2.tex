\chapter{Photogrammetry, Depth Fusion, and Apple Capture APIs}
\label{ch:theory1}

This chapter explains the geometric and algorithmic ideas behind the capture pipelines used in the thesis application. It first reviews \textbf{photogrammetry} and the classical chain \textbf{structure from motion (SfM) $\rightarrow$ multi-view stereo (MVS) $\rightarrow$ Poisson surface reconstruction} \cite{luhmann2014photogrammetry,lowe2004sift,furukawa2010pmvs,kazhdan2006poisson}. It then describes \textbf{depth fusion} with a \textbf{truncated signed distance function (TSDF)} as used in real-time RGB-D and LiDAR systems \cite{newcombe2011kinectfusion}, which underpins ARKit-style scene meshes that RoomPlan builds upon. A comparison between \textbf{image-only} object reconstruction and \textbf{depth-assisted} room understanding clarifies why Object Capture and RoomPlan behave differently. Finally, the chapter maps these ideas to Apple's \textbf{Object Capture} and \textbf{RoomPlan} APIs, documents the \texttt{CapturedRoom} data model, and summarises related work in AR interior design and usability evaluation.

\section{Motivation}
\label{sec:motivation}

Users redesign interiors more confidently when they can \textbf{see} alternatives in context. Traditional representations (2D plans, catalog photos, or material swatches) omit depth, occlusion, and the relation between existing objects and new ones. Augmented reality can composite virtual furniture into a live video stream, but that mode ties the experience to being physically present and holding the device. If the room is first captured as a structured 3D model, the user can reopen and edit that model later: the scan becomes a \textbf{persistent spatial substrate} for experimentation.

Research datasets such as ScanNet \cite{dai2017scannet} demonstrated that indoor applications benefit from joint \textbf{geometry} and \textbf{semantics} (which surfaces are walls, which objects are chairs or tables). RoomPlan brings a consumer subset of that idea to supported iPhones and iPads: it outputs not only geometry but labelled entities with rough dimensions. This thesis uses that output as the basis for \textbf{furniture replacement}, substituting USDZ models for detected instances, which goes beyond merely placing a free-floating object on a manually identified floor plane.

\section{Photogrammetry and the Classical Reconstruction Pipeline}
\label{sec:photogrammetry}

\subsection{Definition and triangulation}

\textbf{Photogrammetry} is the discipline of extracting metric information from photographs \cite{luhmann2014photogrammetry}. In 3D reconstruction, the elementary geometric operation is \textbf{triangulation}: corresponding points in two or more calibrated images determine a 3D point by intersecting rays. Stable triangulation requires \textbf{baseline} between cameras and sufficient \textbf{overlap} so that the same surface points appear in multiple views.

\subsection{From features to textured mesh}

A widely used multi-view pipeline proceeds in stages \cite{luhmann2014photogrammetry,lowe2004sift,furukawa2010pmvs,kazhdan2006poisson}:

\begin{enumerate}
    \item \textbf{Feature detection and matching}: Distinctive keypoints (e.g.\ SIFT \cite{lowe2004sift}) are extracted and matched across images.

    \item \textbf{Structure from Motion}: Camera intrinsics and extrinsics are estimated together with a \emph{sparse} 3D point cloud. \textbf{Bundle adjustment} refines parameters by minimising reprojection error across all observations. Symbolically, one minimises $\sum_{i,j} \|\mathbf{x}_{ij} - \pi(\mathbf{P}_j, \mathbf{X}_i)\|^2$ over projection matrices $\mathbf{P}_j$ and points $\mathbf{X}_i$, where $\mathbf{x}_{ij}$ are measured image points and $\pi$ is the projection function.

    \item \textbf{Multi-view stereo}: Dense correspondence and depth estimation across views yield a dense point cloud or per-view depth maps \cite{furukawa2010pmvs}.

    \item \textbf{Surface reconstruction}: The dense samples are converted to a watertight or oriented surface, commonly using \textbf{Poisson surface reconstruction} \cite{kazhdan2006poisson}, which solves for an indicator function whose gradient aligns with surface normals, then extracts a mesh (e.g.\ Marching Cubes).

    \item \textbf{Texture mapping}: The mesh is parameterised; colours are blended from source images onto the surface.
\end{enumerate}

\section{Depth Fusion and TSDF-Based Scene Meshing}
\label{sec:depth_fusion}

Room-scale tracking on mobile devices fuses \textbf{depth} (LiDAR or stereo) with \textbf{visual--inertial odometry}. A standard volumetric representation is the \textbf{TSDF}: for each voxel in a bounded volume, one stores a (truncated) signed distance to the nearest surface along with a weight; each new depth frame updates voxels along viewing rays \cite{newcombe2011kinectfusion}. Over time, noise averages down and a coherent surface emerges. The mesh shown in AR debugging views is typically an isosurface of that field.

This reconstruction is \textbf{driven by measured depth}: textureless walls still contribute if the depth sensor returns reliable values. By contrast, MVS in photogrammetry relies on \textbf{photometric consistency} and can fail on untextured or specular surfaces. Semantic interpretation (which planar patch is a ``wall'' and which blob is a ``sofa'') is not solved by the TSDF alone; RoomPlan adds learning-based detection and classification on top of ARKit scene understanding.

\section{Image-Only versus Depth-Assisted Reconstruction}

\subsection{Object Capture}

\texttt{ObjectCaptureSession} guides the user around an object so that views overlap; \texttt{PhotogrammetrySession} reconstructs a mesh and materials, outputting \textbf{USDZ}. That format is well supported in RealityKit and matches the furniture assets used in the editor.

\subsection{Room Plan and \texttt{CapturedRoom}}

Room Plan exposes types such as walls, doors, windows, and \texttt{CapturedRoom.Object} instances with \texttt{category}, \texttt{dimensions}, and \texttt{transform}. Apple continues to extend taxonomy and behaviour \cite{apple2024roomplan2}. Because \texttt{CapturedRoom} conforms to \texttt{Codable}, applications can persist scans as JSON or similar, as done in the implementation (Chapter~\ref{ch:implementation}) under a per-room file in the Documents hierarchy.

\section{Limitations}
\label{sec:limitations_capture}

Photogrammetry remains sensitive to glass, mirrors, and uniform surfaces. Room Plan can miss small objects, merge adjacent pieces, or mislabel categories; coarse bounding boxes are not CAD precision. These issues motivate manual touch-up in the editor and, for research-oriented quality, export to external tools, including 3DGS training pipelines discussed in Chapter~\ref{ch:theory2}.
